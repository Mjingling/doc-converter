# EP01 缘起：媳妇的文档烦恼、我的架构蓝图，还有一位 AI 结对程序员

> 系列第 1 篇 | 成品 Demo：DocMorph 主项目 | 预计阅读 10 分钟

## 故事的开始

媳妇在行政岗，日常被各种文档折磨：

- 老板发来 30 张扫描件图片，"帮我合成一个 PDF"
- 合同 PDF 太大，微信发不出去，"帮我压缩一下"
- 十几个 Word 要转 PDF，"一个一个导出太慢了"
- 桌面堆满各种转换网站的弹窗广告，"这网站还要传文件？合同能随便上传吗？"

市面上的工具要么收费、要么塞广告、要么要把文件传到别人的服务器——
合同、报表这类文件，**隐私是底线**。

那就自己做一个：**全部本地处理、没有广告、顺手做得可爱一点**。
可爱不是附加题——是给媳妇做的工具，桌面宠物是必须的。

问题是：一个行政文档工具箱 + 桌面宠物，前端、Rust、打包一条龙，
我一个人要写到猴年马月？

答案就是本系列的主角之一：**大模型**。这个项目是我和 AI 编程助手
结对完成的——我提需求、做决策、把关质量，它出方案、写代码、查 bug。
下面 8 篇教程既教你怎么把这个应用做出来，
也教你怎么用同样的方式指挥大模型干活。

## 成品长什么样

先跑起来看看（本仓库根目录就是成品 DocMorph）：

```bash
# 仓库根目录
yarn install
yarn tauri dev
```

你会看到：

1. 主窗口：左侧导航 30+ 项功能（合并、拆分、压缩、加密、图片转 PDF……）
2. 设置里打开「桌面宠物」，屏幕右下角出现一个小机器人
3. 鼠标摸它冒爱心，戳它会有反应，右键有菜单
4. 在主窗口跑一个批量任务，宠物头顶的气泡会实时显示进度条，
   完成后它开心地蹦一下

整个系列 8 篇，就是把这个东西从零做出来。

## 分工：哪些交给 AI，哪些自己把门？

开工前先说清楚人和大模型的分工，这决定了后面每一集的写法：

| 活儿 | 谁干 | 为什么 |
|------|------|--------|
| 需求定义、功能取舍 | 人 | 只有你知道媳妇到底痛在哪 |
| 技术选型大方向 | 人定调、AI 参谋 | AI 能给对比表，但拍板的是你 |
| 脚手架、样板代码 | AI | 重复性高、模式固定，AI 的舒适区 |
| 核心逻辑（如 PDF 引擎） | AI 起草、人审读 | 必须逐行读懂，编译和测试代替不了你的理解 |
| 运行验证 | 机器 | `cargo check`/`vite build`/单测是唯一的裁判 |
| 验收 | 人 | 最后一定要在真机上给媳妇跑一遍 |

> **AI 协作贴士**：给大模型提需求时，把「背景 + 目标 + 约束」一次说清，
> 比如「Tauri 2 + Vue 3，要做透明置顶小窗口，macOS 要过沙箱」。
> 信息给得越全，返工越少——后面每集的开头都会附上当集的关键 prompt 思路。

## 为什么选 Tauri 2

需求列出来，技术选型就清晰了：

| 需求 | 推论 |
|------|------|
| 文件本地处理、性能要好 | 要有真正的后端语言 → Rust |
| 安装包小、内存占用低 | 排除 Electron（100MB+ 起步） |
| 透明置顶小窗口（桌宠） | 需要原生窗口能力 |
| 前端要写得快、组件生态好 | Vue 3 + Naive UI |
| 跨平台（媳妇用 Mac，同事用 Windows） | Tauri 官方支持 |

Tauri 2 的组合拳：**WebView 画界面 + Rust 写引擎 + IPC 打通两边**。
安装包通常只有 10MB 上下，内存是 Electron 方案的几分之一。

## 架构蓝图

整个应用的架构一图说清：

```
┌──────────────────────────── 前端（Vue 3）────────────────────────────┐
│  主窗口 Home.vue                    宠物窗口 PetWindow.vue            │
│  ├─ 30+ 功能面板                    ├─ AssistantAvatar 机器人形象     │
│  ├─ AI 助手 / 摘要 / 翻译           ├─ 空闲行为（眨眼/打盹/张望）      │
│  └─ 设置 / 历史                     └─ 气泡（进度/小贴士/庆祝）        │
└───────────────┬───────────────────────────────┬─────────────────────┘
                │ invoke（调用命令）              │ emit/listen（跨窗口事件）
┌───────────────▼───────────────────────────────▼─────────────────────┐
│                        Rust 后端（src-tauri）                        │
│  commands/  ← Tauri 命令（薄封装，参数校验）                          │
│  engine/    ← 真正干活的引擎：pdf.rs（lopdf）/ convert.rs / ai.rs    │
└──────────────────────────────────────────────────────────────────────┘
```

三个关键设计决策，后面每篇都会展开：

1. **宠物窗口与主窗口共用同一份前端代码**，靠 `index.html?window=pet`
   这个 query 分流渲染（EP06 详解）
2. **命令层薄、引擎层厚**：`commands/` 只做参数转换，逻辑在 `engine/`，
   方便单测（EP05 详解）
3. **跨窗口用 Tauri 全局事件**，不共享状态，只广播事实（EP06 详解）

## 环境准备

开始写代码之前，把工具链装好：

```bash
# Node.js 22+（推荐用版本管理器，如 n / fnm / nvm）
node -v

# Rust（rustup 一条龙）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustc --version

# macOS：Xcode 命令行工具
xcode-select --install

# Tauri CLI 已在项目 devDependencies 里，无需全局安装
```

Windows 用户额外需要：Microsoft C++ Build Tools、WebView2 Runtime
（Win11 自带）。

验证方式：随便找个 Tauri 官方模板 `npm run tauri dev` 能弹出窗口即可。
